# Instructions for AI coding agents
## Roadmap

Перед началом работы прочитай `docs/ROADMAP.md`.

Работай только над текущим этапом.

Не начинай следующий этап без прямого запроса пользователя.

После завершения задачи обновляй состояние соответствующих пунктов
в `docs/ROADMAP.md`.

Не отмечай пункт выполненным, если функциональность не была
реализована и проверена.

Перед началом любой работы прочитай:

- PROJECT.md

Если задача затрагивает архитектуру, также проверь:

- docs/ARCHITECTURE.md
- docs/ROADMAP.md

## Правила работы

Не меняй архитектурные решения из PROJECT.md без явного запроса пользователя.

Не пытайся реализовать весь roadmap за один раз.

Работай только над текущим этапом.

После изменений:

1. проверь TypeScript;
2. проверь lint;
3. выполни npm run build;
4. исправь найденные ошибки.

Не удаляй существующий функционал без необходимости.

Не заменяй рабочие реализации mock-данными.

Не создавай отдельные сущности БД для конкретных привычек.

Используй существующую универсальную систему Habit/HabitEntry.

## Git

Не выполняй destructive Git-команды без явного разрешения.

Перед commit покажи изменения.

После завершения законченного этапа:

- git status
- build
- commit

Если настроен GitHub remote:
- push в main

## Контекст

Если пользователь просит новую функцию, сначала сопоставь её
с существующей архитектурой проекта.

Предпочитай расширение существующей системы созданию
параллельной реализации.
