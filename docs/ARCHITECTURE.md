# Архитектура Этапов 1–3

Документ описывает реализацию требований `PROJECT.md`, не заменяя спецификацию.

## Слои

- `app/` собирает layout и страницы; `App.tsx` не содержит бизнес-логики.
- `components/` и `features/today/` отображают состояние и передают действия в hook.
- Hooks управляют подписками, состояниями загрузки/ошибок и сменой локального дня.
- `services/habit-service.ts` читает привычки, атомарно сохраняет отметки и добавляет количества.
- `services/duration-service.ts` проверяет ввод времени, сохраняет минуты и вычисляет оценки.
- `services/duration-statistics-service.ts` вычисляет последние 7 календарных дней из записей.
- `db/` содержит Dexie, версионированную схему и seed.
- `models/` содержит discriminated unions для универсальных сущностей.
- `lib/local-date.ts` отвечает за проверку и форматирование календарной даты.

## Habit и HabitEntry

`Habit` имеет общий ID, название, описание, порядок, временные метки и `archivedAt`.
Типы: `boolean`, `amount`, `duration`, `rating`. У `amount` есть цель и единица
измерения; у `duration` единица — минуты и есть массив `ratingRanges`.
Ввод реализован для `boolean`, `amount` и `duration`; отдельный тип `rating`
зарезервирован для будущего использования.

`HabitEntry` содержит `habitId`, локальную дату, тип и временные метки.
Boolean-запись хранит ровно одно состояние: `success`, `failure`, `no-data`.
Amount-запись хранит фактическое числовое `value`. Статус и процент не дублируются
в БД: сервис вычисляет `success` при `value >= habit.target`, `in-progress` для
положительного количества ниже цели и `no-data` для отсутствующего результата.
Только процент ограничивается 100%; фактическое количество не обрезается.

Duration-запись хранит целое `minutes` от 0 до 1440. `0` — явный результат,
отсутствие записи — `null` в представлении (без оценки). Строка времени, emoji
и rating не сохраняются в `HabitEntry`. Изменение времени заменяет дневной итог.

`DurationRatingRange` содержит `id`, `label`, `emoji`, `minMinutes`, `maxMinutes`.
Границы включены; последний `maxMinutes: null` означает открытый конец. Сервис
проверяет покрытие с нуля без пропусков/пересечений, уникальность ID и целые границы.
Конфигурация находится в каждой duration-привычке, первоначальные диапазоны —
в `db/duration-defaults.ts`. Текущие границы документированы в README/ROADMAP.
Замена конфигурации пересчитывает оценки в сегодняшнем и историческом представлениях,
сохраняя фактические минуты. Пользовательский экран настройки пока не реализован.

## IndexedDB

Имя БД: `zadachnik`, версия Dexie: `2` (нативная версия IndexedDB — `20`).

| Таблица | Первичный ключ | Дополнительные индексы |
| --- | --- | --- |
| `habits` | `id` | `type`, `order` |
| `habitEntries` | `[habitId+date]` | `habitId`, `date`, `type` |

Составной первичный ключ обеспечивает одну запись на привычку и день. Сервис
в одной read/write-транзакции проверяет существование, тип и архивность привычки,
затем выполняет `put`. Повторная отметка заменяет результат, сохраняя `createdAt`.

Для amount-трекера чтение текущего значения, прибавление и `put` выполняются
в одной read/write-транзакции. Одновременные добавления из разных вкладок
не теряются. Принимаются положительные целые безопасные числа; сумма также
проверяется на точность. Запись с несовместимым типом или некорректным значением
не перезаписывается. Для Этапа 2 модели и схема версии 1 уже поддерживали воду;
тогда миграция не требовалась.

Миграция v1 → v2 добавляет отсутствующие `ratingRanges` существующим duration-привычкам
`gaming` и `social-media`. Таблицы/индексы сохраняются. Имена, временные метки,
архивность и вся история не меняются; удалённые seed-привычки не восстанавливаются,
уже сохранённая конфигурация не заменяется. Новая БД сразу получает диапазоны в seed.

Seed выполняется событием Dexie `populate` в транзакции создания БД:
8 boolean-привычек, вода (цель 2000 мл) и 2 duration-привычки. При обычном
повторном открытии seed не запускается и пользовательские данные не меняются.
Записи `HabitEntry` заранее не создаются.

Отсутствие записи отображается как `no-data`, никогда как `failure`. Явный выбор
«Нет данных» сохраняет запись со статусом `no-data`. Отметки других дней остаются
в БД. Архивирование не реализовано как пользовательская функция; чтение учитывает
`archivedAt`, не удаляя историю.

Dexie `liveQuery` обновляет интерфейс при изменении хранилища, включая другие
вкладки. Ошибки открытия, чтения и записи показываются пользователю.

`AmountTracker` отображает рассчитанное сервисом состояние и передаёт действия
в `useTodayHabits`. Hook подписывает страницу на boolean- и amount-результаты,
хранит состояния ввода и сохранения отдельно для каждой привычки и дня.
Ручной ввод проверяет `parseAmountInput` в сервисе; поле очищается только после
успешной записи. Быстрые кнопки прибавляют 200/400 мл к тому же `HabitEntry`.
Цель берётся из `AmountHabit` (для воды в seed — 2000 мл).

`DurationTracker` — один компонент для обеих duration-привычек. Hook держит
черновик часов/минут отдельно для каждой привычки и даты. Если черновика нет,
форма выводит сохранённые минуты как часы/минуты; после успешного сохранения
она снова следует данным IndexedDB. Ошибка не очищает введённое время.
Пустое отдельное поле считается нулём, но полностью пустая форма не сохраняется.

## Недельная статистика duration

По прямому запросу пользователя в Этап 3 включён минимальный недельный обзор
игр и соцсетей в существующем разделе «Статистика». Это не полный Этап 7.
Период — сегодняшний локальный день и шесть предыдущих, включая обе границы.
Календарные даты строятся `date-fns/addDays`, без вычитания фиксированных 24 часов.

Сервис читает активные duration-привычки и реальные записи периода в одной
read-транзакции; вычисляет сумму минут, число заполненных/пустых дней,
среднее по дням с записью, текущий rating каждого дня и распределение категорий.
Ноль участвует в среднем; отсутствие записи не превращается в ноль или неудачу.
Среднее при отсутствии всех записей равно `null`, а не 0. Дробная точность
среднего сохраняется до форматирования UI. Агрегаты в БД не записываются.

График Recharts и доступная таблица используют один массив семи дней.
Пропуски остаются `null`; точные значения видны без hover. Если ResizeObserver
недоступен, остаётся таблица. Страница статистики загружается через React.lazy,
чтобы библиотека графиков не увеличивала начальную загрузку «Сегодня».
Dexie liveQuery и hook локальной даты обновляют статистику после записей и в полночь.

## Локальный день

Ключ дня — валидированная строка `yyyy-MM-dd`, построенная date-fns из локальных
компонентов `Date`. UTC-день через `toISOString().slice(0, 10)` не используется.
ISO UTC используется только для временных меток `createdAt` / `updatedAt`.

Следующая полночь вычисляется календарно, а не прибавлением фиксированных 24 часов,
чтобы учитывать переходы летнего времени. Hook обновляет день по таймеру, при
фокусе, изменении видимости вкладки и периодически проверяет смену часового пояса.
Перед сохранением повторно проверяется текущая дата, чтобы устаревшая вкладка
не записала результат за вчера.

## Границы этапа

Интерфейс использует мобильную базу CSS, затем `min-width` для больших экранов.
Viewport учитывает iOS safe-area; элементы управления рассчитаны на касания.
Целевой браузер iPhone — Safari 16.4+ (минимум Tailwind CSS 4), JavaScript сборки
также нацелен на Safari 16.4. Наличие IndexedDB проверяется до открытия БД;
ошибка доступа обрабатывается тем же экраном повторной загрузки.
WebKit с профилем iPhone входит в E2E-проверки. Проверка на физическом устройстве
остаётся отдельной ручной проверкой, эмуляция её не подменяет.

Каталог `dist` автоматически публикуется на Vercel по HTTPS из ветки `main`.
Текущая hash-навигация работает на статическом хостинге.

Календарь, задачи, цели и настройки — заглушки. Пока нет полной статистики,
streak, настройки привычек, backup, PWA и синхронизации.
Будущие сервисы статистики и streak должны оставаться в `services/` согласно
`PROJECT.md`.
