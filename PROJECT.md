# Задачник

## Цель проекта

Личное web-приложение для отслеживания привычек,
задач, целей и долгосрочной статистики.

Основные периоды анализа:

- день;
- неделя;
- месяц;
- 3 месяца;
- 6 месяцев;
- год.

---
## Mobile / iOS

Приложение должно быть mobile-first и корректно работать
в Safari на актуальных версиях iOS.

Основной сценарий ежедневного использования предполагает смартфон.

Минимальная ширина интерфейса: примерно 320–375 px.

Не использовать hover как единственный способ взаимодействия.

Интерактивные элементы должны быть удобны для touch-интерфейса.

В дальнейшем приложение должно поддерживать PWA и установку
на домашний экран iOS.

Первая версия должна быть пригодна для публикации через HTTPS
и использования с iPhone через интернет.

## Мобильные устройства

- Интерфейс проектируется mobile-first и поддерживает Safari на iPhone.
- Адаптивная вёрстка начинается с ширины 320–375 px, без горизонтального скролла.
- Кнопки удобны для касаний; действия не зависят от hover.
- Используется viewport meta tag и учитываются safe-area iOS.
- Возможности браузера проверяются до использования; ошибки хранилища видны пользователю.
- PWA, Service Worker, полноценный offline mode и установка на устройство не входят в Этап 1.
- Будущая публикация: GitHub + Vercel, доступ через HTTPS из интернета.

В будущем:
- PWA;
- Supabase;
- синхронизация устройств.

# Основные сущности

## Habit

Универсальная сущность привычки.

Типы:

- boolean
- amount
- duration
- rating

Не создавать отдельные сущности для каждой привычки.

## HabitEntry

Хранит результат Habit за конкретный календарный день.

Состояния boolean:

- success
- failure
- no-data

Отсутствие записи не считается failure.

---

# Начальные привычки

## Boolean

- Воздержание
- Английский каждый день
- Чтение книги каждый день
- Подъём до 8:00
- Без чипсов
- Без газировок и соков
- Без энергетиков
- Без фастфуда

## Amount

### Вода

Цель:

2000 мл / день.

Быстрые действия:

- +200 мл
- +400 мл
- произвольное значение

Допускается перевыполнение цели.

---

## Duration / Rating

### Игры

Сохранять фактическое время.

Категории:

- 0–2 часа — отлично
- 2–4 часа — хорошо
- 4–6 часов — нейтрально
- около 6 часов — плохо
- >6 часов — очень плохо

### Социальные сети

- 0–1 час — отлично
- 1–1.5 часа — хорошо
- >1.5 часа — плохо

Границы должны быть редактируемыми.

# Архитектурные правила

1. Не делать монолитный App.tsx.
2. Не создавать отдельную таблицу для каждой привычки.
3. Использовать Habit + HabitEntry.
4. Не использовать any без необходимости.
5. IndexedDB вынести в db/.
6. Статистику вынести в services/.
7. Streak вынести в отдельный service.
8. Не использовать UTC-день вместо локального календарного дня.
9. Архивирование Habit не должно удалять историю.
10. Графики должны использовать реальные данные.
11. После каждого этапа npm run build должен проходить успешно.

# Git

Основная ветка:

main

После каждого законченного этапа:

1. проверить приложение;
2. npm run build;
3. git status;
4. commit;
5. push в GitHub.

Не коммитить:

- node_modules
- секреты
- .env с приватными значениями
- локальные пользовательские данные
