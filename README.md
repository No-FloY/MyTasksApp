# Задачник

Личное local-first приложение для ежедневных и недельных привычек, задач и целей: 23 привычки
в категориях, вода, тренировки, игры и соцсети, оценка дня и недели, календарь истории, заметки, серии, задачи,
долгосрочные цели, статистика, настройки привычек и локальные резервные копии.
Данные хранятся в IndexedDB.
Состояние этапов разработки и результаты проверок — в [roadmap](docs/ROADMAP.md).

Production: [Задачник](https://my-tasks-app-xi.vercel.app/).

## Установка и работа без сети

На iPhone откройте production в Safari → «Поделиться» → «На экран „Домой“».
Запустите «Задачник» с новой иконки: приложение открывается отдельно от браузерной
панели. На поддерживаемых desktop/Android-браузерах используйте стандартный пункт
установки в меню или адресной строке браузера, если он доступен.

Первый запуск установленного приложения выполните с интернетом. В «Настройках»
дождитесь сообщения «Приложение готово к работе без подключения». После этого
можно закрыть и снова открыть приложение без сети, пользоваться всеми шестью
разделами, сохранять привычки, воду, время, задачи и цели, менять настройки,
скачивать и восстанавливать локальные JSON-копии. Индикатор «Нет подключения»
не блокирует работу; после возвращения сети перезапуск не требуется.

Без сети недоступны первая загрузка, загрузка новой версии и внешние ссылки.
Кэш приложения и данные хранятся на устройстве; удаление данных сайта или
вытеснение хранилища браузером может убрать их. Регулярно сохраняйте backup.
Устройства и разные браузерные профили **не синхронизируются**.

Safari и установленное приложение могут иметь отдельное хранилище. Если после
установки ваши записи отсутствуют, скачайте backup в Safari и восстановите его
в установленном приложении через «Настройки». Импорт заменяет данные текущей
копии приложения; данные Safari остаются. Автоматического переноса нет.
Первое online-открытие требуется именно установленной копии, а не только Safari.
Это ограничение [хранилища Home Screen в WebKit](https://webkit.org/blog/14787/webkit-features-in-safari-17-2/).

При новой версии появляется сообщение «Доступна новая версия приложения».
Сохраните введённые значения, нажмите «Обновить» и подтвердите. Если открыты другие
окна приложения, сохраните изменения в них и закройте их, затем повторите.
«Позже» оставляет текущую версию; обновление доступно и в «Настройках».
Проверки выполняются при открытии, возвращении в приложение/сеть и периодически.
Обновление кода сохраняет IndexedDB, настройки и текущий адрес раздела.

## Запуск

Нужен Node.js 24 LTS с npm; также поддерживаются 22.13+ в ветке 22 и версии 26+.

```sh
npm ci
npm run dev
```

Откройте адрес, который покажет Vite (обычно http://localhost:5173).
Сборка и её локальный просмотр:

```sh
npm run build
npm run preview
```

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run test:pwa-update
npm run build
```

Для браузерных тестов нужен установленный Google Chrome и движок WebKit:

```sh
npx playwright install webkit
```

Playwright запускает
временные изолированные контексты браузера; личные данные пользователя не затрагиваются.
Unit-тесты используют fake-indexeddb; E2E проверяют настоящую IndexedDB в Chrome.
Те же сценарии запускаются в WebKit с профилем iPhone, включая ширины 320, 375 и 390 px.
Для проверки опубликованной версии задайте `PLAYWRIGHT_BASE_URL` перед запуском
`npm run test:e2e`: тогда локальный Vite-сервер не запускается.
В используемой сборке Playwright WebKit `context.setOffline(true)` ломает
SW-навигацию («WebKit encountered an internal error») даже при активном контроллере
и доступном precache. Три проверки такого offline-транспорта (общая PWA,
тренировки, питание/уборка) пропущены в WebKit и полностью выполняются в Chrome.
Также остаётся прежний пропуск незавершённого native time input в WebKit.
Регистрация SW, реальное обновление A → B,
сохранность БД и backup проверяются в обоих движках. Дополнительно в обоих движках
проверены загрузка нового lazy-раздела, закрытие последней страницы, повторный
запуск, новые привычки и backup/import при полностью остановленном тестовом сервере.
Ограничение эмуляции: [Playwright #42775](https://github.com/microsoft/playwright/issues/42775).
Offline-запуск установленного приложения на iPhone — вручную.
Обычный E2E запускает production build/preview. `test:pwa-update` собирает две
разные версии в `.artifacts`, переключает отдельный временный HTTP-сервер и
проверяет настоящий цикл обновления, другие окна, offline и сохранность БД.
Service Worker работает только в production build по HTTPS или на localhost;
`npm run dev` его не регистрирует. Не используйте один origin для dev и ранее
закэшированного preview: для разработки можно выбрать другой порт.

## Использование

На странице «Сегодня» выберите для привычки «Успех», «Неудача» или «Нет данных».
Отметку можно изменить. Все три состояния сохраняются локально и восстанавливаются
после перезагрузки. Если записи за день нет, отображается «Нет данных».

В карточке «Вода» кнопки `+200 мл` и `+400 мл` добавляют количество к выпитому
за сегодня. Для другой порции введите положительное целое число миллилитров
в поле «Сколько добавить, мл» и нажмите «Добавить». Поле очищается после сохранения.
При достижении дневной цели (изначально 2000 мл) появляется «Цель достигнута». Можно продолжать добавлять воду:
фактическое количество сохраняется полностью, а шкала ограничена 100%.
Пустой день не считается неудачей. В полночь отображается результат нового дня,
история предыдущего остаётся в IndexedDB.

В карточках времени укажите часы и минуты, затем нажмите «Сохранить время».
Это итог за день: повторное сохранение заменяет его. Можно сохранить 0 ч 0 мин;
пустая форма не создаёт запись. Допускаются целые часы 0–24 и минуты 0–59,
в сумме не более 24 часов. Сохранённый результат и форма восстанавливаются после reload.
Emoji и оценка вычисляются из фактических минут по диапазонам привычки:

| Оценка | Игры | Соцсети |
| --- | --- | --- |
| 😄 Отлично | 0:00–2:00 | 0:00–1:00 |
| 🙂 Хорошо | 2:01–4:00 | 1:01–1:30 |
| 😐 Нейтрально | 4:01–5:29 | — |
| 🙁 Плохо | 5:30–6:00 | от 1:31 |
| 😡 Очень плохо | от 6:01 | — |

Обе границы включены. «Около 6 часов» для игр означает последние полчаса до
6:00 включительно. Диапазоны можно посмотреть под формой ввода. Они хранятся
в `Habit.ratingRanges`; пороги, подписи и emoji можно изменить в «Настройках».

В «Статистике» доступны обзор, привычки, вода, игры, соцсети, задачи и текущие цели.
Период выбирается над сводкой и сохраняется в адресе страницы после reload:

- «7 дней» — сегодня и шесть предыдущих локальных календарных дней;
- «Месяц» — с первого числа текущего месяца по сегодня;
- «Предыдущий месяц» — весь предыдущий календарный месяц;
- «3 месяца», «6 месяцев», «Год» — скользящий период: от даты на 3/6/12 месяцев
  раньше сегодняшней плюс один день до сегодня;
- «Свой период» — обе выбранные даты включены, окончание не позже сегодня,
  длина не более 3660 дней.

Процент boolean-привычки = `success / (success + failure) × 100`. Пропуски и
`no-data` не считаются неудачами. Общий процент использует сумму успехов и явных
оценок всех привычек, а не среднее их процентов. Серии в статистике ограничены
выбранным периодом; текущая заканчивается последним днём периода.

Для воды показаны сумма, среднее, минимум, максимум, заполненные дни и дни
достижения цели. Среднее считается по дням с записью, доля успешных дней —
`дни с value >= target / дни с записью × 100`. Явный ноль учитывается,
значения выше цели сохраняются полностью. График показывает фактическое количество
и линию текущей цели привычки.

Игры и соцсети показаны отдельно: фактические минуты, сумма, минимум, максимум,
распределение текущих оценок/emoji и два средних. Среднее по записям делит сумму
на число заполненных дней; среднее за день отслеживания — на число дней, когда
привычка существовала в периоде. Пропуски остаются пропусками на графике,
а сохранённое `0:00` учитывается как результат. Без записей средние отсутствуют;
округление до минут выполняется только при отображении.

Дни до создания привычки и после её архивации не увеличивают число пропусков.
Более ранняя запись, внесённая через календарь, сдвигает начало отслеживания;
сохранённые записи после архивации также видны. Архивные привычки сохраняют
историю и помечены «Архив». Цели воды и rating ranges берутся из текущей
конфигурации Habit: исторические версии настроек не сохранялись.

Задача входит в период по дате дедлайна. Вовремя, поздно, не выполнено,
просрочено, отменено и ещё запланировано показаны отдельно.
`relevantTasks = completedOnTime + completedLate + failed + overdue`;
`OnTimeRate = completedOnTime / relevantTasks × 100`,
`DeviationRate = (completedLate + failed + overdue) / relevantTasks × 100`.
В интерфейсе DeviationRate называется «Отклонение от плана». Отменённые,
ещё не просроченные и старые выполненные задачи без корректного `completedAt`
исключены из обоих коэффициентов и показаны отдельными счётчиками.

Сводка целей показывает текущее состояние, независимо от периода: активные,
завершённые, не достигнутые, отменённые, просроченные и средний прогресс активных.
Архивные цели учитываются отдельным числом и исключены из этих показателей.
История процентов не строится, поскольку снимки прогресса не сохранялись.

Для периодов от 15 дней добавляется динамика по неделям с понедельника по
воскресенье; первая и последняя недели ограничены выбранным диапазоном.
Отдельные графики показывают успехи привычек, задачи вовремя, дни достижения
цели воды и среднее время игр/соцсетей. Дополнительная оценка дня и недели
вычисляется по открытой формуле, описанной ниже.
Рядом с графиками есть текстовые значения и таблицы, подсказки доступны касанием.
Если период пересекает границу года, даты в таблицах и подсказках включают год.
Пустой знаменатель означает «Нет данных», а не 0%, NaN или Infinity;
пустые графики не выводятся. Все показатели вычисляются из реальных записей,
отдельные агрегаты и оценки в БД не сохраняются.

День определяется по локальной календарной дате устройства. При наступлении
полуночи и возвращении в открытую вкладку дата обновляется.

В «Календаре» выберите день в сетке месяца, чтобы посмотреть и исправить его
результаты. Неделя начинается с понедельника; стрелки переключают месяцы,
«Сегодня» возвращает текущий месяц и выбирает сегодняшний день. Выбор и месяц
восстанавливаются после reload. В будущих днях можно посмотреть запланированные
задачи; ввод результатов привычек доступен только за текущие и прошлые дни.
Сегодня обведено и подчёркнуто, выбранный день выделен фоном. Сетка поддерживает
клавиатуру: Tab, Enter/Space и стрелки между датами.

Число вида `3/11` показывает заполненность, `✓` означает, что все активные привычки
отмечены; это не оценка успешности дня. Прочерк означает отсутствие результатов.
В календаре поле воды «Итог за день, мл» заменяет сохранённое количество (включая 0).
Boolean и время редактируются теми же трекерами, что и на странице «Сегодня».
Исправления сразу учитываются в календаре и статистике выбранного периода.

К сохранённому результату можно добавить заметку до 2000 символов. В блоке
«Серии и доля успехов» показаны boolean-привычки за всю историю до выбранной даты:
серия, заканчивающаяся этим днём, лучшая серия и доля успехов среди явных оценок.
Пропуски и «Нет данных» прерывают серию, но не учитываются как неудачи в проценте.

Данные принадлежат origin браузера: `localhost` и `127.0.0.1`, разные порты,
браузеры и профили имеют разные хранилища. Для повседневного использования открывайте
один адрес. Очистка данных сайта удалит локальные записи. Сохраняйте резервные копии
через «Настройки». Синхронизация между устройствами пока отсутствует.

В разделе «Задачи» нажмите «Добавить задачу», заполните название, дату и приоритет.
Описание и время необязательны. Можно планировать будущие дни и добавлять задачи
задним числом. Название ограничено 200 символами, описание — 5000.
У активной задачи есть кнопка выполнения; дополнительные действия позволяют
редактировать, удалить, отметить как не выполненную или отменить задачу.
Удаление, неудача и отмена требуют подтверждения. Выполненные задачи сохраняются
и могут быть возвращены в активные. «Не выполнена» (`failed`) и «Отменена»
(`cancelled`) — конечные состояния: вернуть их в активные или выполнить нельзя;
содержимое и связь с целью сохраняются.

Активные задачи распределяются между «Просроченными», «Сегодня» и «Предстоящими»;
выполненные, не выполненные и отменённые видны в отдельных группах. Задача со
временем просрочена после локального срока `HH:mm:00.000`; без времени — после
конца указанного локального дня. Равенство срока считается выполнением вовремя.
У выполненной задачи сравнивается `completedAt` с дедлайном, поэтому карточка
различает выполнение вовремя и с опозданием. Просроченность вычисляется при
отображении и обновляется в открытой вкладке; она не записывается в статус.
Внутри активных групп порядок: дата, время (без времени — в конце дня), приоритет
от высокого к низкому, дата создания и ID. Выполненные показываются по времени
выполнения от новых к старым; не выполненные и отменённые — по последнему изменению.

На «Сегодня» доступен компактный список активных задач дня с выполнением, а календарь
показывает задачи выбранной даты и их статусы, в том числе для будущих дней.
Правки появляются сразу и сохраняются после reload. IndexedDB v3 добавляет таблицу
`tasks`, сохраняя прежние привычки, результаты, заметки и историю.

В «Целях» создайте долгосрочный результат с названием, описанием и необязательным
дедлайном. Откройте карточку, чтобы добавить этапы, связать задачи или изменить
статус. Цели можно завершить, отменить, отметить неудачу, вернуть в активные,
архивировать и восстановить из архива. Удаление требует подтверждения.

Обычный этап отмечается выполненным или невыполненным. Числовой этап хранит
текущее и целевое значения: например, 17 из 30 откликов. Фактическое число
может превышать цель, а вклад этапа в прогресс ограничен 100%. Названия и значения
можно исправлять; порядок добавления сохраняется после перезагрузки.

В автоматическом режиме процент цели — среднее по этапам с одинаковым весом.
Выполненный обычный этап даёт 100%, невыполненный — 0%; числовой — долю
текущего значения от целевого. Без этапов прогресс равен 0%. В ручном режиме
задайте любой процент от 0 до 100. Завершение цели меняет статус, сохраняя
фактический прогресс; достижение 100% само по себе не меняет статус.

В подробностях цели можно привязать существующую задачу, перейти к ней или
снять связь. Одна задача относится максимум к одной цели. Для переноса сначала
отвяжите её от предыдущей цели. Задачи не входят в процент цели. При удалении
цели её этапы удаляются, а задачи остаются с прежними данными и статусами.

IndexedDB v4 добавляет таблицы `goals`, `goalMilestones` и индекс `tasks.goalId`
без перезаписи прежней истории. Всё хранится локально; открытые вкладки одного
адреса получают изменения через liveQuery. Дедлайн цели — локальная дата без времени.
Этап 7 не меняет версию v4, не добавляет таблиц и не переписывает старые записи.
Статистика читает согласованные данные в одной read-транзакции: записи привычек
и задачи — по индексам даты за период, привычки, цели и этапы — целиком.
При необходимости один дополнительный запрос исторических ключей уточняет
начало отслеживания для записей задним числом; запросов на каждый день нет.

## Структура

```text
src/
  app/               # сборка приложения и навигация
  components/
    layout/          # общий каркас
    ui/              # локальные компоненты shadcn/ui
  features/today/     # boolean, amount и duration/rating trackers
  features/habits/    # общие формы и hook результатов выбранного дня
  features/calendar/ # месячная сетка, история, заметки и серии
  features/tasks/    # задачи, формы, дневные блоки и подписки
  features/goals/    # цели, этапы, связанные задачи и формы
  features/statistics/ # выбор периода, сводка, графики и таблицы
  features/settings/ # настройки привычек, архив и резервные копии
  hooks/             # локальный день, текущее время и параметры навигации
  models/            # строгие Habit, HabitEntry, Task, Goal и GoalMilestone
  db/                # Dexie schema и initial seed
  pwa/               # регистрация SW и подтверждаемое обновление
  services/          # результаты, задачи, цели, оценки и серии
    statistics/      # периоды и чистые расчёты привычек, воды, времени, задач и целей
  lib/               # локальная дата и общие утилиты
e2e/                 # браузерные сценарии
docs/                # roadmap и описание архитектуры
```

React + TypeScript + Vite, Tailwind CSS, shadcn/ui, Dexie, date-fns.
Recharts отображает дневные и недельные графики; модуль статистики загружается отдельно.
Компоненты shadcn/ui находятся в `src/components/ui`, настройки генератора —
в `components.json`, alias `@/` указывает на `src/`.

## iPhone и мобильный интерфейс

CSS использует мобильную базу и расширяется через `min-width`. Навигация на телефоне
показывает все шесть разделов сеткой, элементы управления имеют области нажатия
не меньше 44×44 px. Viewport включает `viewport-fit=cover`, отступы учитывают safe-area.
Действия доступны касанием и клавиатурой, без зависимости от hover.

Целевой минимум — Safari/iOS 16.4, соответствующий требованиям
[Tailwind CSS 4](https://tailwindcss.com/docs/compatibility). Vite явно учитывает
Safari 16.4 при сборке JavaScript. WebKit с профилем iPhone проверяется автоматически;
проверка на физическом iPhone пока не выполнялась.

Каталог `dist` публикуется по HTTPS на Vercel автоматически после push в `main`.
Hash-навигация не требует серверных rewrite-правил. Manifest, Service Worker,
offline shell и установка реализованы через `vite-plugin-pwa` / Workbox.
Автоматизация WebKit не воспроизводит установку с экрана «Домой» и системные
safe-area физического iPhone; их нужно проверить на устройстве.

Использованы официальные инструкции [Vite](https://vite.dev/guide/),
[Tailwind CSS](https://tailwindcss.com/docs/installation/using-vite)
и [shadcn/ui](https://ui.shadcn.com/docs/installation/vite).

## Настройки и резервные копии

В «Настройках» показаны активные и архивированные привычки, их тип, единицы,
цель и диапазоны. Можно изменить название, описание, категорию, дневную цель количества,
границы, подписи и emoji существующих категорий времени. Тип и единицы измерения
не меняются: записанные числа должны сохранять смысл. Отдельный тип `rating`
по-прежнему зарезервирован; у него доступны только общие настройки.

Новая цель воды и новые диапазоны применяются ко всей истории. Например, после
изменения цели с 2000 на 2500 мл запись 2200 мл остаётся 2200 мл, но перестаёт
считаться достижением цели. Изменение диапазона может изменить старую оценку,
не меняя фактических минут. Это ограничение объясняется в форме редактирования.
Исторические версии настроек и снимки целей в записях не добавлялись.

Архивирование скрывает привычку на «Сегодня», сохраняя её определение и все
записи. В календаре есть просмотр архивных результатов и заметок выбранного дня;
статистика прошлых периодов остаётся доступной. «Восстановить» возвращает привычку
в ежедневный список. Для редактирования результата сначала восстановите привычку.
Поле `archivedAt` хранит только текущую дату архивации: интервалы пребывания
в архиве после восстановления не отслеживаются. Отдельного удаления привычек
или кнопки очистки всей базы нет.

«Скачать резервную копию» сохраняет JSON с локальной датой в имени:
`zadachnik-backup-2026-10-20.json`. Файл содержит метаданные
`app: "zadachnik"`, `formatVersion: 3`, `exportedAt` (ISO timestamp) и `data`
с массивами `habits`, `habitEntries`, `tasks`, `goals`, `goalMilestones`.
Сохраняются ID, даты, заметки, настройки привычек, архив, статусы, этапы и связи
задач с целями. Отдельных пользовательских настроек вне этих таблиц сейчас нет.
Код, кэш, данные Git и серверов в копию не входят. Файл не зашифрован.

«Восстановить из файла» открывает обычный выбор JSON-файла (до 50 МиБ).
До записи проверяются приложение и версия, структура, обязательные поля,
даты, значения, диапазоны, дубликаты и связи. Неподдерживаемая новая версия
получает отдельное объяснение. Форматы 1 и 2 поддерживаются: определения формата 1 дополняются
категорией и конфигурацией количества; отсутствие schedule означает ежедневное расписание.
Состав копии сохраняется — новые привычки при импорте не добавляются. Неизвестные поля отклоняются,
чтобы не потерять их молча.
Порядок свойств JSON не важен.

После проверки показаны дата и количество объектов. Можно скачать текущую копию
и отменить операцию. «Продолжить импорт» открывает отдельное подтверждение:
**текущие локальные данные будут полностью заменены данными файла**.
Объединение баз не выполняется. Пустая валидная копия также требует подтверждения.
Все пять таблиц заменяются в одной транзакции: при ошибке изменения откатываются,
а прежняя база остаётся целой. После успеха открытые экраны и вкладки обновляются;
ручная очистка кэша не нужна. Импорт не запускает initial seed заново.

Backup formatVersion 3 сохраняет расписание и независим от версии Dexie: текущая схема v6,
состав пяти таблиц прежний. Export/import используют стандартные Blob/download
и file input, доступные Safari; на iPhone копию можно сохранить в «Файлы».
Cloud backup и синхронизация не реализованы. PWA использует тот же backup formatVersion 3.

## Категории и тренировки

«Сегодня» группирует привычки в шесть категорий. Пустые категории скрыты;
их можно выбрать в настройках существующей привычки. Категории раскрыты по умолчанию,
сворачиваются кнопкой и всегда показывают число заполненных и ожидаемых отметок.

| Категория | Начальные привычки |
| --- | --- |
| Еда и вода (`food_water`) | Вода; без чипсов, газировок/соков, энергетиков, фастфуда, сладкого и шоколада; без алкоголя; завтрак, обед, ужин |
| Тренировка (`training`) | Отжимания, пресс, приседания, подтягивания, пройти 10 км, тренировка |
| Быт и режим (`routine`) | Подъём до 8:00; уборка раз в неделю |
| Учёба и работа (`study_work`) | Изначально пуста |
| Экранное время (`screen_time`) | Игры, социальные сети |
| Саморазвитие (`self_development`) | Воздержание, английский, чтение |

Отжимания, пресс и приседания: цель 100 повторений, кнопка +10.
Подтягивания: цель 15, кнопка +1. «Указать итог дня» раскрывает ручной ввод,
который **заменяет** итог, включая 0. Быстрые кнопки прибавляют к текущему итогу.
Например, 130/100 сохраняется как 130 и показывается как 130%; шкала и вклад
в оценку ограничены 100%. Вода по-прежнему использует +200/+400 и ручное прибавление.
В календаре количество всегда редактируется абсолютным итогом выбранного дня.

«Без сладкого и шоколада», «Пройти 10 км» и «Тренировка» используют обычные
«Успех / Неудача / Нет данных». Факт тренировки отмечается вручную; повторения
его автоматически не меняют. Настройки и backup хранят `quickActions` и
`manualMode` как конфигурацию общего amount tracker, без отдельных таблиц упражнений.
Редактор быстрых кнопок в интерфейс пока не добавлен.

При первом открытии новой версии существующая БД переходит с Dexie v4/v5 на v6.
Категории назначаются по стабильным ID, поэтому переименованные привычки сохраняются.
Миграция дополняет определения и добавляет только отсутствующие 12 новых Habit этапа 10;
их `createdAt` равен моменту обновления. Старые ID, названия, цели, архивность,
временные метки и все записи сохраняются. Повторное открытие ничего не добавляет.
Импорт backup — отдельная операция замены: даже пустая или старая копия не запускает seed.

«Без алкоголя»: «Не пил» сохраняет success, «Пил» — failure, «Нет данных» — no-data.
У завтрака, обеда и ужина используются «Был / Не было / Нет данных». Несколько
употреблений алкоголя в один день остаются одним днём с алкоголем; объём не учитывается.

Уборка — одна цель на календарную неделю с понедельника по воскресенье.
Отметка любого дня недели меняет один общий результат этой недели, включая календарь
и заметку. Отдельный фактический день уборки не хранится. Незавершённая неделя без
отметки — no-data; полностью отслеживаемая завершённая неделя без отметки — вычисляемое невыполнение.
Явное «Нет данных» остаётся no-data. Отсутствие записи не создаёт новую запись в БД.
Уборка без назначенного дня не входит в DayScore и ежедневную заполненность.
Неполные крайние недели выбранного периода и недели с частичной доступностью
привычки без записи остаются no-data. Явные результаты учитываются один раз.

Расписание универсально: ежедневное, выбранные дни недели или одна цель за неделю
с необязательным назначенным днём. При назначенном дне недельная привычка входит
в дневную оценку только этого дня. Полный редактор расписания пока не добавлен.

Статистика показывает дни с алкоголем, без алкоголя, без данных, долю дней без
алкоголя среди заполненных и отдельный показатель текущего месяца. Для каждого
приёма пищи доступны успехи, пропуски и no-data; полный день питания вычисляется
только при success у всех трёх приёмов. Уборка считается по неделям, а не по дням.

## Как считаются оценки

Оценка привычки: успех — 100, неудача — 0; количество —
`min(value / target, 1) × 100`. Для времени используется позиция подходящего
диапазона в списке от лучшего к худшему: `100 × (1 − index / (count − 1))`.
Пять уровней дают 100/75/50/25/0; три — 100/50/0; единственный уровень — 100.
Исходные минуты и количество не меняются. Отдельный зарезервированный тип `rating`
не имеет шкалы и исключён из оценки и её знаменателя; записи сохраняются.

`CategoryScore` — среднее оценок заполненных привычек категории.
`DayScore` — среднее оценок категорий с данными: каждая такая категория весит одинаково.
Отсутствующая запись и boolean `no-data` исключены из средних; явный ноль количества
или времени является результатом. Полностью пустой день имеет «Нет данных», а не 0%.

`DataCoverage = заполненные / ожидаемые по расписанию показатели × 100%`. Ниже 50% рядом
с оценкой выводится «Недостаточно данных для полной оценки» вместо интерпретации дня.
До даты создания привычка не ожидается, поэтому новые упражнения не уменьшают
заполненность прошлых дней. Внесённый задним числом результат сдвигает начало
отслеживания. С даты архивации пустые дни привычки исключены; сохранённые факты
остаются в расчётах. История периодов архивации после восстановления не хранится.

`WeeklyScore` относится к календарной неделе: с понедельника до выбранной даты.
Дневные показатели берутся из дней с заполненностью **не ниже 50%**. Внутри каждой
категории недельная привычка добавляет ровно одну оценку; затем категории с данными
усредняются с равным весом. Недельная отметка может дать оценку даже при недостатке
ежедневных данных. Назначенный день не добавляет вторую копию недельной цели.
Средняя заполненность включает пустые доступные дни как 0%, но исключает даты
без доступных показателей. Лучший/слабый день и средние категорий берутся по тем же
достаточно заполненным дням; при равенстве показана более ранняя дата.
Полные, частичные, пустые дни и даты без показателей посчитаны отдельно.

Оценки показаны на «Сегодня», в выбранном дне календаря и в статистике.
Прежние подробные показатели сохранены. Для упражнений доступны сумма, среднее
по дням с записью, дни достижения цели и максимум за день; для 10 км и тренировок —
успехи, неудачи и доля успехов. Пропуски не превращаются в неудачи.

Текущие категории, цели и диапазоны применяются ко всей истории. Изменение
категории может изменить исторический DayScore из-за равного веса категорий,
но не меняет ни одного HabitEntry. Исторических снимков настроек нет.
Расчёты не округляются до агрегации; в сводке дня/недели проценты показаны целыми.
